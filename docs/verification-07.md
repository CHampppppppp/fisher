## 实现范围

- 先同步 AGENTS.md 阶段规则，再递增扩展现有 Game、Controller、UI；没有更换框架或创建第二套测试状态。
- 无持鱼时 E/interact 拾取最近合法 groundedDead，玩家脚部到尸体位置三维距离≤2米且不穿商店，不要求面向。持鱼时仍优先执行原放鱼。每条一格、容量10、不堆叠；满包保留地面实体，活鱼/escaped/重复实体不入包。
- 原 ID 从 fish 转入生产 inventory（state:inventoryDead），食用后从 inventory 移除并写入 consumedFish（state:consumed）。真实捕获 ID 分配也避开初始背包 ID。所有列表随状态深拷贝。
- 食用恢复 sprat12/bass20/tuna30/golden40 饥饿，不恢复HP，最高100；满饥饿拒绝并保留物品，相同 ID 不能重复消费。有效输入立即进食，再由下一固定步更新饥饿和伤害；菜单进食不推进模拟。
- 饥饿每 tick -1/120（每秒0.5），更新后严格低于20时HP每 tick -1/30（每秒2），范围均[0,100]。使用初值/最近恢复值和整数 tick 计数计算，避免累计浮点误差导致恰好20误扣血。食用不重置已有HP损失。
- Tab/openInventory 替换前序主动释放鼠标机制：打开背包暂停全部模拟并清除输入，保留钓鱼会话。关闭清除输入，原 running 可回 running/鼠标自由；点击场景重新锁定，不误触攻击/抛竿。从 pause 打开或期间失焦/隐藏后关闭仍回 pause，必须点击继续。暂停菜单也有背包入口，菜单拒绝移动/攻击/拾取/放鱼等游戏动作。
- HP0立即 dead、释放鼠标、清除输入、冻结所有计时，显示生命耗尽与明确重新开始。dead 拒绝继续、移动、攻击、食用及拾取，只有确认 restart 或测试 reset 可以新开一局。重开HP/饥饿100、金币0、空背包/鱼/消费记录、combat 拳头，恢复原 reset 的初始鱼种RNG；清历史后发布一次 restart。
- reset.initial 支持有限[0,100]的player.hp/hunger和严格{id,species}背包数组，最多10、ID不重复且不与初始fish重复；全量校验后提交。初始HP0也立即dead，不推进tick。
- UI按原ID选择每个物品并显示名称、恢复值和容量，菜单内显示当前生命/饥饿；HUD实时数值/比例及低饥饿伤害提示。事件增加 inventory/eat/player_damage/game_over/restart，仍使用同一有界生产日志。
- 不提前实现交易、存档、其他武器、生存奖励或Boss。
